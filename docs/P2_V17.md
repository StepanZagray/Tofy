# P2 v17 — two overnight runs: stability stack vs Q/PTRM training fixes

Builds on v16 (per-batch RMS norm, capped rollout, no default retarget). Both
runs are motivated by the research notes
[`docs/research/fable5/02-delta-vs-absolute-latents.md`](research/fable5/02-delta-vs-absolute-latents.md)
and
[`docs/research/fable5/05-recursion-sigreg-q-stability.md`](research/fable5/05-recursion-sigreg-q-stability.md):
note 05's headline findings are that Q ranking has been exactly at chance in
every run so far and that the v15 latent ran at ~5.7x unit scale, coupling the
depth-extrapolation explosion, the PTRM pass@k collapse, and Q miscalibration
to one non-contractive operator.

Baseline for all gates: the v16 eval report
(`p2-output-v16/eval_report_64ep_v5.json` from `scripts/p2_v16_train_eval.sh`).
Run it first if it does not exist — every gate below is relative to it.

## Run 1 — `p2-output-v17-stable` (dynamics stability stack)

**Hypothesis:** the matched-compute/rollout explosion is caused by
(a) the recursion operator being trained only at depth 2 with no incentive to
be contractive, (b) SIGReg being too weak per-dimension on the flattened
4096-d latent, and (c) the missing identity path in the `y` update. Fixing all
three should make deterministic matched compute approximately flat in depth
and improve open-loop rollout without hurting one-step MSE.

| Flag | Value | Source |
|------|-------|--------|
| `--residual-y-update` | on | note 02 §4.1-1: pre-LN pattern `y = rms_norm(y + block(y + z))`, identity path for the static grid majority |
| `--warm-start-y` | on | note 02 §4.1-2: init recursion `y` from the encoded state; refine toward next state instead of rebuilding from `x` |
| `--sigreg-spatial` | on | note 05 §2.2 / E4: per-position statistic `(B*H*W) x C` instead of flattened `B x 4096` |
| `--randomize-depth` | on | note 05 §2.1 / E2: sample outer/inner depth uniformly in `1..=configured` each step; teaches approximate idempotence at the target |
| `--outer-steps 8` | 8 | widens the randomized depth range to `1..=8` so evaluated depths are inside the training contract |

```bash
cargo run --release --features cudnn -- p2-train \
  --device cuda \
  --lessons dynamics,exploration,sequential,q_calibration,falsification \
  --hidden-dim 64 --action-dim 32 \
  --physical-batch 1024 --grad-accum 1 \
  --steps-per-lesson 4096 \
  --sigreg-weight 0.003 \
  --outer-steps 8 --randomize-depth \
  --residual-y-update --warm-start-y --sigreg-spatial \
  --checkpoint-every-steps 100 \
  --output-dir p2-output-v17-stable
```

Note: at `--outer-steps 8` the mean sampled depth is ~4.5, so per-step cost is
roughly 2x v16; re-measure the largest stable physical batch before committing
to 1024 (record the chosen batch/accum pair with the run).

### Gates (vs v16 baseline)

| Gate | Pass criterion |
|------|----------------|
| G1 matched compute | `deterministic_matched_compute` flat within 2x across the reported depths (8, 16, 32, 64 at `--ptrm-k 1,2,4,8`); no geometric blowup |
| G2 one-step MSE | ≤ v16 one-step latent MSE; hard reject if degraded >10% |
| G3 open-loop rollout | rollout MSE @8 improves ≥20% over v16 |
| G4 latent shape | `latent_covariance_frobenius` within 2x of `sqrt(dim)` = 64 |
| G5 copy-forward tripwire | closed-loop MSE does not regress; on action-heavy segments the model must not converge to identity (note 02 §4.3 risk for residual/warm-start) |

### Credit / discredit

- **Credited** if G1–G3 all pass: the "non-contractive operator + weak SIGReg
  + missing identity path" account of the explosion is confirmed; promote the
  stack to the v18 default and only then tune Q on top of it.
- **Discredited** if G1 fails despite depth randomization: depth training does
  not buy contraction; escalate to the explicit idempotence penalty (note 05
  E7) before spending more runs on this axis.
- **Partial** if G1 passes but G2/G3 fail: contraction and accuracy are in
  tension; this run bundles four changes (deliberately — it is a "does the
  whole stable stack work" run, against note 02's one-diff-per-run advice), so
  attribution requires follow-up single-diff runs. Do not credit any
  individual flag from this run alone.

## Run 2 — `p2-output-v17-exp-qnoise` (Q/PTRM training fixes, no arch changes)

**Hypothesis (note 05 §2.3–2.4):** Q ranking at chance and pass@k ≈ 0 are
caused by training wiring, not architecture: (a) Q BCE gradients leak into the
dynamics through `q_logit(pool(y))`, giving the model a perverse incentive to
move `y`; (b) the fixed absolute `q_mse_threshold` cuts a nonstationary MSE
distribution, saturating labels (v11 all-positive, v13 re-saturation); (c) the
model never sees z-noise at train time, so eval-time PTRM noise is pure
unlearned perturbation. This run fixes all three while keeping the v16
architecture and `outer_steps 2` untouched.

| Flag | Value | Source |
|------|-------|--------|
| `--stop-grad-q-y` | on | note 05 §2.3: detach `y` in the Q BCE and surprise paths; Q becomes a pure observer |
| `--q-quantile-targets` | on | note 05 §2.3: labels from the batch MSE quantile — balanced by construction, threshold-free |
| `--train-z-noise 0.03` | 0.03 | note 05 §2.4: denoising training so the recursion learns to contract injected z-noise; 0.03 is mid-range of the E0 sweep grid |
| `--randomize-depth` | on | mild depth robustness at the v16 default `outer_steps 2` (sampled `1..=2`); intentionally *not* combined with `--outer-steps 8` to keep this run arch/compute-equivalent to v16 |

```bash
cargo run --release --features cudnn -- p2-train \
  --device cuda \
  --lessons dynamics,exploration,sequential,q_calibration,falsification \
  --hidden-dim 64 --action-dim 32 \
  --physical-batch 1024 --grad-accum 1 \
  --steps-per-lesson 4096 \
  --sigreg-weight 0.003 \
  --randomize-depth \
  --stop-grad-q-y --q-quantile-targets --train-z-noise 0.03 \
  --checkpoint-every-steps 100 \
  --output-dir p2-output-v17-exp-qnoise
```

### Gates (vs v16 baseline)

| Gate | Pass criterion |
|------|----------------|
| G1 Q calibration | balanced accuracy > 0.85, `saturated = false`, `confident_error_rate` < 0.2 (note 05 E3 gate) |
| G2 Q ranking | `q_oracle_rank_accuracy@4` > 0.4 (chance is 0.25) at the best sigma from the eval noise sweep |
| G3 PTRM recovery | at eval `--ptrm-noise 0.03` (matching train noise): `disagreement` finite and small, and pass@2 ≥ pass@1 |
| G4 no dynamics tax | one-step MSE and rollout @4/@8 within 10% of v16 (the fixes must not cost prediction quality) |

### Credit / discredit

- **Credited** if G1–G3 pass with G4 held: the Q/PTRM failures were training
  wiring, and "PTRM noise helps ranking" gets its first actual demonstration.
  These flags become defaults; no architecture change was needed.
- **Discredited** if G1 passes but G2/G3 still sit at chance: calibration was
  never the binding constraint on ranking; the remaining suspects are the
  best-of-K ranking loss itself (replace with margin ranking on detached
  per-trajectory MSE, note 05 E6) and the every-inner-step noise injection
  site (single-injection/annealed schedule, note 05 E5) — both are
  architecture/schedule changes this run deliberately excluded.
- **Discredited** if G4 fails: `train_z_noise 0.03` is too aggressive for the
  unnormalized `z`; retry at 0.01 before drawing conclusions about (a)/(b).

## Eval

Standard report (both runs; substitute `OUT`):

```bash
OUT=p2-output-v17-stable   # or p2-output-v17-exp-qnoise
CKPT="$OUT/model.best.safetensors"; [[ -f "$CKPT" ]] || CKPT="$OUT/model.safetensors"
Q=$(python3 -c "import json; print(json.load(open('$OUT/config.json'))['q_mse_threshold'])")

cargo run --release --features cudnn -- p2-eval \
  --device cuda --physical-batch 64 \
  --checkpoint "$CKPT" \
  --train-config "$OUT/config.json" \
  --synthetic-episodes 64 --ptrm-k 1,2,4,8 \
  --q-mse-threshold "$Q" \
  --output "$OUT/eval_report_64ep_v5.json"
```

PTRM noise sweep (required for run 2's G2/G3 best-sigma selection; cheap
eval-only sanity for run 1):

```bash
for sigma in 0.003 0.01 0.03 0.1; do
  cargo run --release --features cudnn -- p2-eval \
    --device cuda --physical-batch 64 \
    --checkpoint "$CKPT" \
    --train-config "$OUT/config.json" \
    --synthetic-episodes 64 --ptrm-k 1,2,4,8 \
    --ptrm-noise "$sigma" \
    --q-mse-threshold "$Q" \
    --output "$OUT/eval_report_64ep_v5_noise${sigma}.json"
done
```

Matched compute is reported inside the standard eval
(`deterministic_matched_compute`, at `ptrm_k x trained outer_steps`): depths
8/16/32/64 for run 1, 2/4/8/16 for run 2. Report schema remains
`p2.eval_report.v5`.

On completion, update `docs/RESULTS_P2.md` with the metrics and exact
commands, including the measured batch/accum pair for run 1.

## Overnight pipeline (`scripts/p2_v17_night.sh`)

```bash
scripts/p2_v17_night.sh
# physical_batch=512 grad_accum=1 (8GB GPU, outer-steps=8 + spatial SIGReg)
```

Sequence:

1. **Pretest** (fresh start only — skipped when `p2-output-v17-stable/checkpoints/` exists):  
   `scripts/p2_v17_pretest.sh all` — v11 PTRM noise sweep (eval-only) + two 512-step micro-trains (spatial baseline vs residual+warm stack). Results under `p2-output-v17-night/pretest/`.
2. **Run 1** — `p2-output-v17-stable` full train + eval.
3. **Between-run PTRM sweep** on stable checkpoint (σ ∈ {0.003, 0.01, 0.03, 0.1}).
4. **Run 2** — `p2-output-v17-exp-qnoise` full train + eval.
5. **Summary** — `p2-output-v17-night/summary.json`.

Skip pretest: `PRETEST=0 scripts/p2_v17_night.sh`.

A background watcher (`scripts/p2_v17_watch_continue.sh`) is running for the
current session (started mid-run): after stable eval it runs the between-run
sweep and ensures run 2 starts if the original night script does not chain cleanly.
