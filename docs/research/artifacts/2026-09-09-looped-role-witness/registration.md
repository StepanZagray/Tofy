## Exact claim and decision

For each frozen initial/C7-final core independently, a shared linear query fitted with synthetic agent/goal identity labels can localize those roles and feed the already frozen C8 affine action readout. This is privileged fitting supervision, with only raw model features used for inference. It tests a prerequisite; no ARC score, end-to-end optimization claim, model promotion, or infeasibility proof follows.

C8's oracle pooling may succeed from coordinates alone. Counterexample: every query has the same tokens H_j=(x_j,y_j,sqrt(128-x_j²-y_j²),0,...), independent of object colors. Every token has RMS1. True-role indices expose direction; any feature-only pooling is constant across queries. Actual C9 raw features need testing. With standardized X and lambda>0, ridge has the unique solution (XᵀX/N+lambdaI)^(-1)Xᵀ(Y-meanY)/N. A positive target-versus-all-other margin is a finite constructive shared-linear-selector witness, not a population theorem. Failed ridge is not linear infeasibility or absence of role information.

## Pre-execution clarifications from independent review

Recorded before all real fits. Joint token/target permutation checks apply to scores and soft weights generally; hard first-index argmax is compared only where the maximum is unique, or via the complete maximizer set. Ties in the identical-token negative control are intentionally not hard-permutation-equivariant. C8's affine intercept field is named `label_mean`: use ((pool-mean)/scale) @ coefficients + label_mean exactly. Ordinary native policy means the frozen-core known-features-policy.f32 outputs, not any fitted C9 readout. These clarify controls and artifact naming without changing the registered fit, thresholds, populations, or outputs.

Before any real fit, require each fitting `visible_cells` to contain exactly64 categorical cells and exactly one color2 and one color3. Cell indexj is row-major(y*8+x) and equals current-token indexj, matching task render_cells/patchify and the final64 current slots; verify this mapping against retained rows and source, never repair/drop a failing query. Require all fit prefixes and checkpoint hashes match C8 exactly, and frozen C8 oracle-role action accuracy on512 fitting queries >=0.90 before role fitting. No evaluation input is read for this precondition. On evaluation, oracle-policy failure or null/numerical-control failure yields `inconclusive_failed_control`, never an ordinary negative role conclusion. Evaluation controls remain after all four role fits are sealed, preserving the data boundary.

The soft witness has an explicit real-arithmetic translation into C9's head class: queries are sqrt128*alpha*raw role coefficients (one row per role); output weight is transpose(C8 coefficients/feature scale), with bias label_mean - (C8 feature mean/scale) @ coefficients. The hard selector is a separate diagnostic. F32 reference checks do not constitute a CUDA implementation test of these transplanted parameters. No claim about optimizer failure, unique cause, or robust performance follows without a separately registered runtime/held-out confirmation.

Final pre-fit numerical clarification: the null action control is the conjunction of hard<=0.50 and soft<=0.50 for each of both null cores; report every endpoint. For a role whose fitted margin exceeds1e-8, the fitted-target mass check accepts F64 mass>=1-1e-6-1e-12 and F32 mass>=1-1e-6-2*float32_epsilon. These tolerances are numerical acceptance only, not a stronger exact-arithmetic guarantee. Require finite raw/query/softmax outputs in both precisions. A failed eligible mass check is a numerical-control failure and prevents a supported result. When the margin premise fails, mark its mass guarantee ineligible (alpha remains1); do not fabricate a mass failure or silently claim a witness. The finite fitwitness and empirical selection-only routing gate remain separate.
