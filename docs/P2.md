# P2: recursive latent world model

P2's first phase implements the learned latent world model that will replace exact
transition access inside the planner. Closed-loop learned-model planning is a later
gate. The real environment remains authoritative: hidden-goal beliefs change only
after real observations, never because a model rollout predicted success or failure.

## Research contract

P2 combines three deliberately separate ideas:

1. **LeWorldModel training:** encode pixels end to end and minimize next-latent MSE
   plus step-wise SIGReg. SIGReg uses the Epps--Pulley statistic over random unit
   projections; it is not replaced by a covariance penalty, target network, or
   stop-gradient encoder.
2. **Tiny Recursive Model dynamics:** fuse the current-state embedding and action,
   then repeatedly refine a next-state estimate `y` and scratch state `z` with one
   shared two-layer block. The first experiment uses fixed recursion, not learned
   halting.
3. **Probabilistic TRM inference:** when prediction is uncertain, run `K` parallel
   trajectories and inject Gaussian noise into `z` at every deep refinement step.
   A learned `Q_world` head ranks transition candidates. Risk-sensitive planning
   retains the credible set instead of discarding everything except maximum Q.

Dynamics are goal-free. A separate predicate head receives the predicted state and
a **public candidate-goal encoding**. The model never receives
`Scenario.hidden_goal_index`.

Primary references:

- LeWorldModel: <https://arxiv.org/abs/2603.19312>
- Tiny Recursive Model: <https://arxiv.org/abs/2510.04871>
- Probabilistic Tiny Recursive Model: <https://arxiv.org/abs/2605.19943>
- ARC-AGI-3 technical report: <https://arxiv.org/abs/2603.24621>
- Official ARC-AGI toolkit: <https://github.com/arcprize/ARC-AGI>

## ARC-AGI-3 alignment

ARC-AGI-3 exposes one or more categorical 2D frames, the currently available action
IDs, optional coordinates for the complex action, and public game-state metadata. It
does not expose instructions or the win predicate. P2 uses the same outer contract:

- categorical official frames padded to `64 x 64` without interpolation; small
  synthetic grids are copied into the top-left canvas without mixing palette categories;
- simple actions `ACTION1..ACTION5` and `ACTION7`, plus coordinate action `ACTION6`
  (official mapping: 1=up, 2=down, 3=left, 4=right, 5=interact, 6=xy, 7=undo);
- action/response cycles with no-op actions still consuming environment steps;
- level completion, win, and game-over treated as public observations; absent
  recording fields, including action-budget exhaustion, remain masked;
- success and action efficiency reported separately.

The official public set contains 25 game files. Those games and public human
recordings are **transfer evaluation only**: they are never used to fit weights,
select a checkpoint, tune noise, or choose curriculum settings. Private competition
games remain accessible only through the official evaluation harness.

`p2::arc3` imports JSONL recordings written by the official toolkit. It pairs an
observation with the next event because that event contains the action that produced
its frame. `RESET` events are episode boundaries, not learned transitions. Malformed
files fail evaluation with a source/line error rather than becoming an empty split.
When an API response contains animation frames, the importer uses the last frame as
the settled observation while validating every layer.

The repository does not vendor the public files: the human-recording mirror alone is
hundreds of megabytes, and Kaggle/API access may require the user's ARC credentials.
Keeping data external also makes the train/evaluation boundary auditable.

## Synthetic curriculum

Default training follows `docs/P2_ARC3_TRAINING.md` (ArcPad frames, variable status UI,
goal-free dynamics/exploration, Stage 1b lesson order).

Synthetic tasks provide exact transitions and candidate-predicate labels without
exposing the hidden candidate. Lessons change the data distribution rather than
mixing every behavior from the first update:

| Lesson | Episodes | Intended behavior |
|---|---|---|
| `dynamics` | random legal grid actions plus synthetic ACTION6 coordinate interactions | learn local effects, no-ops, and coordinate conditioning |
| `exploration` | 8–12 step goal-free random walks on ordinary maps | early-game dynamics without candidate features |
| `sequential` | exact plan fragments toward one public candidate | learn directed multi-step dynamics and short open-loop rollouts |
| `q_calibration` | same plan fragments as sequential | warm event + Q heads on stable dynamics (stop-grad on `y`) |
| `falsification` | P1C safe multi-candidate probe (`p1c_falsification`) | combine Q, events, and PTRM rank |
| `retarget` | deep false leads and multi-step P1C-hard traces | remain accurate through reversals; PTRM ranking + rollout |

`Q_world` correctness targets are trained throughout all four lessons. PTRM itself
is an inference procedure and does not require a dishonest duplicate
"probabilistic" lesson.

The first model gate evaluates held-out compositions only. P1C-hard remains a
mechanism stress test selected against the sequential baseline, not a representative
estimate of ARC-AGI-3 frequency.

## Model outputs and losses

For current frame `s`, action `a`, and optional candidate features `g`:

```text
x = state_action_encoder(s, a)
y = initial next-state estimate
z = zero scratch state

repeat outer_steps:
    repeat inner_steps:
        z = block(x + y + z [+ noise])
    y = block(y + z)
```

The shared `block` is a v2 residual MLP (`h + MLP(h)`). Training uses
`forward(frames)` end-to-end with absolute next-latent MSE (LeWorldModel recipe).

**Phased training** (`--phased-training`, default on) gates auxiliary losses by
lesson:

| Lesson | next_latent + SIGReg | rollout | Q | events | PTRM rank |
|--------|----------------------|---------|---|--------|-----------|
| dynamics | yes | no | no | no | no |
| exploration | yes | no | no | masked | no |
| sequential | yes | ramp 2→8 | no | no | cadence |
| q_calibration | yes | no | ramp 0→full | ramp 0→full | cadence |
| falsification | yes | no | ramp 0→full | ramp 0→full | cadence (k=4) |
| retarget | yes | ramp 2→8 | yes | yes | cadence |

Event loss reads `stop_grad(y)` by default (`--stop-grad-event-y`); Q keeps full
gradients from predicted `y`. Q head is linear on `y` only (v2 recipe).
Every outer step runs the shared block. **Next-latent supervision averages MSE
over all outer steps**. Event and Q heads read the final step.
The final heads are:

- predicted next-state latent `y`;
- `Q_world`, predicting whether the transition estimate is within a frozen error
  threshold;
- candidate-conditioned public predicate logits for no-op, candidate satisfied,
  candidate irreversibly failed, and exhausted.

The base loss is:

```text
L = L_next_latent + lambda_sigreg * SIGReg(encoder(frames))
    + lambda_event * BCE(public_predicates)
    + lambda_q * BCE(transition_correct)
    + lambda_rollout * L_open_loop   # sequential + retarget only
```

Multi-step lessons add open-loop latent Huber error with horizon ramped
2→4→6→8 within the lesson when phased training is on.

## Evaluation

Evaluation reports use schema `p2.eval_report.v8` and separate three benchmark layers
aligned with https://docs.arcprize.org/ :

1. **World-model metrics** (`synthetic`, optional `arc3` splits): one-step / rollout
   latent error, predicate calibration, Q/PTRM ablations. These are development
   diagnostics, not ARC-AGI-3 competition scores.
2. **Official RHAE** (`official_rhae`, `official_scorecard`): populated only when
   `--scorecard-json` points at a closed scorecard from the official API. RHAE is
   recomputed per https://docs.arcprize.org/methodology from per-level human baselines
   and action counts; the API aggregate `score` is retained as a cross-check.
3. **Recording run counters** (`arc3_recording_runs`): derived from toolkit JSONL when
   `--arc-recordings-dir` is set. Fields mirror scorecard `RunSummary` (actions,
   levels completed, terminal state) but **cannot** produce RHAE without human
   baselines.

World-model metrics:

- one-step and 4/8-step latent error;
- deterministic action-shuffle error ratios and action/no-op coverage, both
  aggregated and broken down by synthetic curriculum source; ratios `<= 1.1`
  fail the action-conditioning gate;
- predicate accuracy, especially hazard false negatives;
- invalid frame/action records rejected fail-closed by the ARC importer;
- Q Brier score, threshold accuracy, balanced accuracy, and saturation flag;
- `pass@K` versus `best-Q@K`, ranking gap, and Q-oracle rank accuracy;
- PTRM disagreement and deterministic trajectory evaluations per transition.

Planner metrics retain P1's success and **oracle-normalized efficiency** for synthetic
tasks. That proxy is not RHAE. Official ARC-AGI-3 RHAE is recorded from scorecard
JSON (`--scorecard-json`) or the online evaluator; recording counters alone are not
RHAE.

The first ablation must compare the same checkpoint under:

- deterministic `K=1`;
- PTRM `K=2,4,8` with a frozen noise sweep;
- extra deterministic recursion at approximately matched compute.

Start with `K=4` only at low-Q, high-disagreement, or irreversible decisions. `K=100`
is not a viable default inside a branching planner.

## Pause and exact resume

Every periodic, paused, and final checkpoint is an atomic directory under
`<output>/checkpoints/`. A bundle contains:

- `model.safetensors`;
- `optimizer.safetensors`, including named first and second AdamW moments;
- `trainer_state.json`, including the optimizer step, next lesson/step cursor,
  completed reports, partial lesson sums, frozen training contract, and runtime trace.

`latest.json` is updated only after all three files have been synced and the complete
directory has been published. Readers ignore staging directories. `SIGINT` and
`SIGTERM` request a pause; the current optimizer update finishes before the bundle is
written. `--max-steps-this-run N` provides the same safe boundary for batch
schedulers and deterministic testing.

Resume accepts a bundle, its `checkpoints` directory, or the run directory. Seed,
curriculum, optimizer, loss, model, and batch fields must match the saved training
contract. Output path, checkpoint cadence, and per-invocation step limit are
operational and may change. The device must match for exact numerical continuation.
Weights-only resume is intentionally unsupported because resetting Adam moments, the
bias-correction clock, or the data cursor changes the training trajectory.

The full staged research plan is [`ARC_AGI_3_PLAN.md`](ARC_AGI_3_PLAN.md).

## CUDA / cuDNN

Train with `--features cudnn --device cuda`. Upstream candle 0.11.0 only runs cuDNN
for *forward* convolution and rewrites weight gradients as a pathological forward
conv; that made stock `--features cudnn` slower than im2col. Tofy patches
`candle-core` via `[patch.crates-io]` → [`vendor/candle-core`](../vendor/candle-core/TOFY_PATCH.md)
to call cudarc's `ConvBackwardFilter` / `ConvBackwardData`. Enabling cuDNN without
that patch is a regression.

Per-step phase timings: `TOFY_P2_STEP_PROFILE=N`. Chrome Trace:
`TOFY_PERF_TRACE=path` with `--features profiling`. For CPU+GPU correlation on
CUDA, use NVIDIA Nsight Systems as the primary profiler:

```bash
nsys profile --trace=cuda,nvtx,osrt,cudnn,cublas --sample=cpu \
  --output=tofy-train \
  cargo run --release --features cudnn -- p2-train --device cuda ...
```

Open the `.nsys-rep` in the Nsight GUI. Keep `TOFY_P2_STEP_PROFILE` /
`TOFY_PERF_TRACE` for cheap host-side phase timings; use `nsys` when optimizing
GPU utilization or host/device stalls. See [`src/perf.rs`](../src/perf.rs).
